# 速率口径修正 + 滚动入场动效

日期：2026-10-13
起因：用户反馈两件事——(1) Token 每秒统计明显不对，按理应该「几十到几百」；
(2) 页面往下滚时看不到元素动起来的效果。

## 一、速率口径（根因与结论）

### 根因

不是分桶代码错，是**指标定义错**。

`total_tokens = 新鲜输入 + 输出 + 缓存读 + 缓存写`，而缓存读占全库 **94.6%**
（codex 94.3% / dsh 97.8% / opencode 97.3% / claude-code 94.0%）。

Codex 每轮把**整个对话上下文重新发一遍**，单轮 `cached_input_tokens` 可达 42.5 万。
所以「每秒 token」测的是**上下文窗口有多大**，不是**干活强度**。

### 三个口径的实测（79,779 个活跃秒）

| 口径 | 中位数 | 平均 | P95 | 峰值 |
| --- | --- | --- | --- | --- |
| `total_tokens`（旧） | 147,899 | 167,186 | 298,307 | 492,729,544 |
| 新鲜输入 + 输出 | 2,292 | 9,082 | 17,363 | 30,996,680 |
| **输出（生成速度）** | **247** | **554** | 1,850 | 1,033,730 |

用户预期的「几十到几百」= 输出 token/秒 的中位数 247 / 平均 554。

### 决策

**主指标改为输出 token/秒（生成速度）**，上下文吞吐降为次要指标单列，
并明确标注「上下文重读，不计入生成速度」。

### 附带发现：会话恢复突发

峰值秒 2026-07-17 00:52:57 有 **2,748 条事件挤在一秒内**（同一会话，仅 363 个不同毫秒）。

原始 rollout 文件 24,081 行 / 3,806 条 `token_count` / 无完全重复行 / 单个 `session_meta`，
但**开头几百毫秒内集中补写**——会话恢复时 Codex 把积压的 `token_count` 一次性刷出，
全部盖上恢复时刻的时间戳。

全库 592 个毫秒出现同刻并发，合计 754M token = **全库 5.65%**。

**处理：聚合层按 (session_id, ts) 去重取首条**，与 `coldStart` 已有的 `ROW_NUMBER()`
口径保持一致。不动采集层、不重建数据库。

## 二、滚动入场动效（根因与结论）

### 根因

动画**全是 CSS 挂载动画，不是滚动触发的**。

`.topbar` / `.stat-row > *` / 各 `.panel` 上的 `animation: fade-up 300ms both`
在**元素挂载那一刻**触发。而切栏渲染成 `null`（Tab 组件，`App.tsx:406`），
切到一栏时该栏所有区块**同时挂载**，于是全部动画在同一瞬间一起放完。

用户切栏后 300ms 内动画已结束，再往下滚时全部处于终态 → **完全没有滚动驱动的动作**。

`useInView`（`Charts.tsx:21`）虽然真的接了 IntersectionObserver，但只覆盖 4 个图表组件，
只驱动折线的 `stroke-dashoffset` 绘制，不驱动区块/卡片入场。

### 决策

新建 `web/src/reveal.tsx`：模块级**单例 IntersectionObserver** + `Reveal` 组件，
用 `data-reveal` / `data-in` 属性驱动 CSS transition，容器级 stagger。

安全约束（必须满足）：
- 不支持 IntersectionObserver 时直接放行，**内容永远可见**
- `prefers-reduced-motion: reduce` 时不位移
- 切栏重挂载后重新观察（新元素重新注册）
